Multi-agent AI executive advisory

Every sentence,
traceable to something true.

An AI advisor that reads a company's business information — financials, pipeline, incidents, board memos, customer feedback, live spreadsheets — and produces an executive brief: risks, opportunities, the assumptions leadership is treating as fact, ranked recommendations, and what changed since last time. Five specialist agents, a grounding gate that verifies every quote against its source in code, a Contrarian that may only attack, and change detection that is computed, not narrated.

The problem

Not “can a model write recommendations?” — “can you trust the sentence it wrote?”

A chief of staff reads the board pack and tells the CEO where the risk is. An LLM can write that brief fluently — and the failure mode is silent: a confident paragraph with an invented number in it is worse than no brief at all. So the hard problem in AI advisory is not fluency. It is making every claim traceable, forcing the analysis to argue against itself, and reporting change by comparison rather than by asking the model what it remembers. That is enforced here in code the prompt cannot reach — not requested in a system prompt.

🔗 Grounded

Every claim carries a verbatim quote. A program checks the quote is actually present in the named source before anything downstream may cite it. A hallucinated figure becomes a dropped claim in the audit log, never a line in the brief.

⚖️ Adversarial

A separate Contrarian agent reviews every finding and may only subtract — sustain, weaken, or drop — then surfaces the assumptions leadership is treating as fact, quoting their own words back with the cheapest test to settle each one.

📈 Diffed

What changed since last time is computed by matching findings across runs and comparing severity — new, escalated, improved, resolved. The model is shown the diff; it is never asked to remember what moved.

The pipeline

Six phases, two gates, one orchestrator

A ChiefOfStaff sequences the agents and checkpoints the brief after every phase. It never calls a brain and never bypasses a gate — the agents apply the grounding checks; the orchestrator only records what survived. Claims that fail verification and findings that lose their evidence are dropped and logged, not shipped.

The centerpiece

The grounding gate

Sixty lines of grounding.py, no LLM in it. Matching normalises whitespace, case and typographic quotes and dashes — so a model that copies correctly is never punished for a curly apostrophe — but a paraphrase, an altered digit, or a quote attributed to the wrong source fails. There is deliberately no “fuzzy” mode: false negatives are cheap, false positives are the whole failure mode.

Claims must quote. The Analyst returns a verbatim quote and a source_id per claim. verify_claims() confirms the normalised quote is a substring of that source. Quotes under 12 characters are rejected as too thin to be evidence.
Findings must cite verified claims. verify_findings() strips any evidence id that is not a verified claim; a finding left with none is dropped, with the reason recorded. A half-grounded finding keeps only its real evidence.
Metrics come from verified claims only. Burn, runway, concentration, DSO, NPS and the rest are extracted after the gate — so every number in a recommendation traces back to a quote that exists.
The prompt can't reach it. The gate is called by the agents, in Python, after each brain decision. No instruction, jailbreak or clever phrasing routes around a substring check.

Verified & not verified

What is proven, and what is only implemented

Exercised offline, every run

42 tests — 7 grounding, 10 signals, 6 diff, 2 audit, 4 heuristic, 6 Claude-contract, 7 end-to-end — plus both demo snapshots, on Python 3.11 and 3.12 in CI. No test makes a network call.

  • The grounding gate stops a hallucinating brain — a test brain invents a quote, mis-attributes a real one and cites a fake id; all three are removed and the half-grounded finding survives on its real evidence.
  • Every evidence id resolves to a real quote — a test re-reads the sources and checks each finding's evidence independently of the gate.
  • Change is computed, not narrated — the week-2 run asserts DSO escalated, the renewal resolved, the objection lifted, and nothing was invented as new.
  • The audit chain detects tampering — a rewritten payload flips verification to false at that entry.

Implemented, not proven known gaps

Stated here at the same confidence as in the repository's own Known gaps section.

  • Grounding is substring-exact. A model that paraphrases a number correctly is dropped along with one that invents it — the intended trade, but a model that struggles to copy verbatim produces thin briefs.
  • Claude findings are matched by title similarity. Two Claude runs may word a risk differently enough to fall under the threshold, producing a spurious resolved + new pair.
  • The Claude path is contract-tested, not live-tested. A stubbed client covers extraction, the repair round and the fallback; a live run needs a key and isn't in CI.
  • The health score is linear, not calibrated; the demo company is fictional and hand-written to contain the contradictions the system is meant to find.

Let it run itself

A GitHub Actions cron re-runs the pipeline, commits the new brief, and Pages redeploys. Continuous, no server.

# install
$ git clone https://github.com/AbdulAlharbi/exec-advisor
$ cd exec-advisor
$ pip install -e ".[dev]"

# analyse the demo company (no key needed)
$ advisor run --brain heuristic

# two weeks later - diffed against the last run
$ advisor run --brain heuristic \
      --sources data/company-week2/sources.yaml

# inspect, list history, verify the audit chain
$ advisor show
$ advisor audit

# 42 tests, no network, ~1s
$ pytest -q

# then open the dashboard
$ open docs/app.html   # or serve docs/ over http

With ANTHROPIC_API_KEY set, the default ADVISOR_BRAIN=auto selects Claude; without it, the rule brain. The source manifest is the whole configuration — point ADVISOR_SOURCES at your own company and the same guarantees apply.
